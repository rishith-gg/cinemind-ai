| D-026 | 2026-10-05 | Upload is a raw-body endpoint (`application/octet-stream`, filename in the query), not multipart. | Streams straight to disk with a hard size cap (rule 7) and needs no `python-multipart` dependency. The generated client supports it. |
| D-027 | 2026-10-05 | Stage cache extended: `Stage.scope_project` (per-project key for stages that write files), `Stage.verify` (cached result ignored if its files are gone), `Stage.persist` (DB write after a run or a cache hit). | Closes the Phase 1 limitation "cached results are not checked against artifact files and not scoped per project". | D-028 | 2026-10-05 | Ingest is one job per media item with stages validate, proxy, thumbnails, waveform; asset state shown in the UI is derived from the latest ingest job. | Matches the existing job model; a failed validate leaves a clear job error and no half-filled asset. |
| D-029 | 2026-10-05 | Proxy encoder chosen by FFmpeg's encoder list (NVENC, VideoToolbox, QSV) with a runtime fallback to libx264. | Rule 8: hardware-aware, always a CPU path. A listed hardware encoder may still fail without the GPU. |
| D-030 | 2026-10-05 | Waveform peaks computed in pure Python (`array`) from 8 kHz mono PCM, 1000 bins, stored as JSON; wavesurfer.js 8.0.1 draws them. | No numpy dependency needed yet; wavesurfer does not have to decode audio in the browser. |
| D-031 | 2026-10-05 | Folder import expands folders by media-like extension only; files named explicitly are always accepted and validated by ffprobe. | Avoids probing `.DS_Store`/sidecar files in bulk while keeping "validate by content" for anything the user picks. |
| D-032 | 2026-10-05 | Test and E2E footage is synthetic (ffmpeg `testsrc2`/`sine`, generated on demand), never committed. | Real sample footage is still needed from the user for acceptance with real camera files. |
| D-033 | 2026-10-05 | ffprobe/ffmpeg run with `-protocol_whitelist file`; playlist-like containers (hls, concat, sdp, rtsp, ...) are rejected after probing; the source is re-checked against `media_roots` (reference) or the project media dir (copy/upload) every time the ingest chain runs. | Found in review: a text playlist inside a root could make FFmpeg read files outside the roots (rule 7). |
| D-034 | 2026-10-09 | Phase 4 libraries, versions checked on PyPI today: `scenedetect` 0.7.1 (pulls `opencv-python` 5.0.0.93 and `numpy` 2.5.3), `opentimelineio` 0.18.1. Dev only: `otio-fcp-adapter` 1.0.0, `otio-cmx3600-adapter` 1.0.0. | Rule 9. OTIO no longer bundles the FCP7 XML and EDL adapters; they are separate packages. `opencv-python` (not `-headless`) because scenedetect depends on that exact package and the two cannot be installed together. |
| D-035 | 2026-10-09 | Shot detection and keyframes are two more stages of the `ingest` chain (`shots`, `keyframes`) and run on the constant-frame-rate proxy. Detector: PySceneDetect `AdaptiveDetector` (`content` selectable), library default thresholds, minimum shot length 0.5 s; all four values are settings and part of the cache key. | One job per clip stays the model (D-028); existing clips pick the new stages up through "Process all". That first run redoes the proxy too: `validate` changed (it now records the nominal rate) and cache keys chain to the stage before. Thresholds are NOT tuned: that needs labelled footage (Phase 13). |
| D-036 | 2026-10-09 | Our own FCP7 XML (xmeml) and CMX3600 EDL writers; the OTIO adapters are used only as independent readers in the round-trip tests. OTIO stays the interchange model and the `.otio` export. | The OTIO `fcp_xml` writer produced empty audio clip items, duplicated `<rate>` elements and unescaped file URLs (checked by running it); the EDL writer truncates clip names into reel names. Writing ~150 lines ourselves gives linked audio, one `<file>` definition per source and exact control of frame numbers. |
| D-037 | 2026-10-09 | Export frame math: a clip's export rate is its nominal rate snapped to a standard rate (24000/1001 ... 120) when it agrees with the measured average within 5 %, else the snapped average. Timeline items are stored in seconds and converted to whole frames on the timeline rate with rationals. Sources at another rate keep their own `<file>` rate and get in/out in timeline-rate frames, with a warning. Timelines start at 01:00:00:00 non-drop; a source's own drop-frame timecode is kept. | Phone clips are variable frame rate: ffprobe reports averages such as 67575/566 for a 120 fps clip, which no NLE timeline can use. Mixed rates cannot be exact (up to one frame off) and an EDL cannot describe them at all, so the user is told. Whether Resolve reads the mixed-rate in/out the same way is what the manual import test decides. |
| D-038 | 2026-10-09 | Keyframes: 1 (shot < 1.5 s), 2 (< 4 s) or 3 per shot, at evenly spaced anchors; at each anchor the sharpest of up to 5 frames within 0.25 s (variance of the Laplacian at 360 px height), never the first or last frame of the shot. Stored as JPEG at proxy size with the sharpness value. | SPEC stage 5 ("sharpest near start/mid/end"). One sequential decode pass. Proxy-size images are enough for SigLIP and face detection later. |
| D-039 | 2026-10-09 | Shot and keyframe ids are hashes of (media id, start frame, end frame[, slot]); persisting re-uses rows whose frames did not change. | Later tables (selects, tags, timeline items) point at shots; re-running detection must not orphan them. |
| D-040 | 2026-10-09 | The "all shots" timeline orders clips by file name (natural order), then shots in source order. Its default frame rate is the rate most clips have (ties: the higher), its size the most common clip size. Optionally clips at other rates are left out. | No capture date is stored yet. It is a test of the export path, not a rough cut: nothing is selected or ranked. |
| D-041 | 2026-10-09 | The nominal frame rate columns are a separate migration (0004), not part of 0003. | 0003 had already been applied to the local database by a running dev server before the columns were added; editing an applied migration would have left that database without them. |
| D-042 | 2026-10-09 | `.env` in the repo root is now really read (`env_file`), and ranks above `cinemind.toml`. Order: environment, `.env`, `cinemind.toml`. Machine-specific values such as `CINEMIND_MEDIA_ROOTS` go in `.env` (gitignored); the tracked `cinemind.toml` keeps `media_roots = []`. | `.env.example` promised this but no `env_file` was set, and the user's footage path would otherwise have been committed in a tracked file (found in review). |
| D-043 | 2026-10-09 | Review fixes: a variable-rate file's length is counted at its average rate and the timeline warns about it; a timeline warns when cuts disappeared because clips were deleted; an EDL is refused above 60 fps or 999 cuts; export downloads go through fetch so failures show a message; `opencv-python` is declared directly. | Code review of the Phase 4 diff. The 120 fps phone clip (7.545 s, average 119.39 fps) would have been declared 905 frames long when it holds about 901. |
| D-044 | 2026-10-09 | FCP7 XML writes one audio clip item per cut (one audio track), not one per channel. | Manual import into DaVinci Resolve 21.1 (free): each audio clip item of a stereo file came in as the full stereo audio, so stereo clips had their sound twice. Resolve is the target editor; FCP7 XML stays the primary export path since it imported without errors and linked every clip. |
| D-045 | 2026-10-09 | Technical quality = two more ingest stages (`quality`, `audio_qc`). They cache raw measurements only; sub-scores, scores and flags are derived in the persist step from the current `[quality]` settings. | Changing a weight or threshold must not cost a video decode, and the stored rows always match the settings shown next to them (rule 6). |
| D-046 | 2026-10-09 | Focus is measured with a re-blur ratio (share of Laplacian energy surviving a sigma-1 blur, with an 8-bit rounding-noise floor), backed by an absolute Laplacian-variance floor. Plain Laplacian variance (what SPEC section 8 names) is still stored. | On the user's frames Laplacian variance alone ranges from 5 to 1600 on untouched frames (content dependent): held-out F1 0.985 with 4 false positives of 55, against 0.997 with 1 for the ratio rule (`eval/results/quality_calibration_2026-10-09`). |
| D-047 | 2026-10-09 | Flag thresholds are calibrated on real frames with synthetic degradations (blur, exposure), grouped 5-fold by clip. Weights, the low-quality limit and all audio thresholds are stated conventions, marked DEFAULT in `quality_config.py`. | No human-labelled footage exists yet. Synthetic labels have a known cause, which is enough to place a threshold, and the limits are written down in EVALUATION.md instead of hidden. Hand labels remain future work (Phase 13). |
| D-048 | 2026-10-09 | Audio is measured on the original file (first audio stream), picture on the proxy. Clipping = share of decoded 16-bit samples at >= 99.9 % of full scale. | The proxy's AAC re-encode changes peaks, so clipping cannot be read from it. Reading the source is non-destructive and uses the same path check as validation. |
| D-049 | 2026-10-09 | Focus is not flagged on frames without tonal range (`spread < flat_spread`); a black shot is reported as black/underexposed only. | A flat frame has no detail that could have been sharp; "out of focus" would be a false statement. |
| D-050 | 2026-10-09 | The library filters and sorts by quality in the browser on the existing media list; no charts or dashboard counts yet. | The roadmap asks for badges, QC overlays, filters and a low-quality list in this phase; the dashboard is Phase 14. Avoids an unused Recharts dependency for now. |
| D-051 | 2026-10-09 | Review fixes for Phase 5: the clip score is recomputed after either quality stage persists; audio too short to gate is not called quiet; `QualityConfig` validates its own consistency; focus score and focus flag share one rule (not judged without tonal range, 0 under the detail floor); detector output is parsed only from the filter's own log lines; an undecodable audio track becomes an `audio_unreadable` flag instead of failing the clip; the API returns the settings a score was computed with; UI wording changed to "Tech score" and "Soft picture". | Code review of the Phase 5 diff. Each was reproduced first: a failed `audio_qc` left a stale clip score, a 0.2 s tone was flagged "too quiet", a metadata title containing `silence_start:` produced fake silence flags, and equal ramp endpoints inverted the focus score. |
| D-052 | 2026-10-10 | Speech to text: faster-whisper 1.2.1 (CTranslate2 4.8.2), versions read from PyPI today. Models are the Systran conversions of Whisper, each pinned to a Hugging Face revision in `core/transcribe_config.py` (revisions and sizes read from the model index today). | CLAUDE.md rule 9. A pinned revision plus the stored engine version makes a transcript reproducible in principle (see D-057 for the limit). |
| D-053 | 2026-10-10 | Models are downloaded only by `cinemind models pull` into `data/models/` and loaded from that folder by path. The transcribe stage never touches the network; a missing model is recorded as `model_missing`, the job still succeeds, and the stage is tried again on the next run (`Stage.verify`). | Rule 1 (no internet during processing). Failing the whole job would hide the picture results of a user who has not downloaded a model, and would make every test and the E2E run depend on a 487 MB download. The state is shown in the clip panel, the Transcripts page, `doctor` and the health endpoint, so it is not silent. |
| D-054 | 2026-10-10 | A stage can name the stages its cache key hangs on (`Stage.upstream`); `transcribe` names only `validate`. Other stages keep the old rule (chained to the stage before). | Transcription is by far the slowest stage (EVALUATION.md section 5). Changing a shot or quality setting must not send audio through the model again. The same option would fix the open Phase 5 item (audio_qc re-measured after keyframe changes); left alone here because it would invalidate every stored audio measurement once. |
| D-055 | 2026-10-10 | Transcript rows are rewritten only when the stage result changed (hash stored in `transcripts.digest`); segment ids are integers. | FTS5 external-content tables need an integer rowid, and later phases will point at segments (selects, embeddings). `persist` runs on every job, also on a cache hit, so without the check every "Process all" would renumber all segments. |
| D-056 | 2026-10-10 | Keyword search = SQLite FTS5 over segment text (external content, triggers), BM25 order, all terms required, each term a prefix match, user input always quoted. `jump_s` is the first word starting with the first term. | The stack names FTS5. Quoting makes FTS5 operators typed by a user plain text instead of a syntax error or an injection. Prefix matching is a cheap stand-in for stemming; semantic search is Phase 9. |
| D-057 | 2026-10-10 | Uncertain segments are marked with Whisper's own limits (`avg_logprob < -1.0`, `compression_ratio > 2.4`; language probability under 0.5), kept, dimmed and labelled. Nothing is hidden or deleted except punctuation-only segments. Decoding settings stay at the library defaults, including the random retries. | On the user's noisy phone clips Whisper produced fluent text for water, music and crowd noise, and two runs on the same clip gave different words and languages. We have no labelled data to justify a filter threshold of our own (rule 3), so the model's own acceptance limits are used and named as such. Turning the retries off would make results repeatable but changes accuracy in a way we have not measured. |
| D-058 | 2026-10-10 | Audio for transcription comes from the original file through our own ffmpeg call (16 kHz mono), not from faster-whisper's built-in decoder and not from the proxy. The PCM reader is shared with the clipping check (`ffmpeg.pcm_chunks`). | Same path check and argument-list rule as every other read of a source file (rule 7); the proxy's AAC re-encode would be a second lossy step. |
| D-059 | 2026-10-10 | WER is measured on Mini LibriSpeech dev-clean-2 (public, CC BY 4.0, fetched by `eval/wer.py fetch` into the gitignored `data/eval/`), a fixed random sample, through the app's own transcribe functions. `jiwer` is a dev dependency. | The roadmap asks for WER on a labelled sample and no hand-corrected transcript of the user's footage exists. | D-060 | 2026-10-10 | Review fixes for Phase 6: the keyword index keeps combining marks inside words (migration 0007); control characters in a search entry end a word instead of reaching FTS5; `audio_unreadable` is retried like `model_missing`; an automatically chosen GPU that fails while decoding falls back to the CPU; retrying or resuming an older job adds the stage rows its chain has gained; `register_chain` rejects an `upstream` name that is not an earlier stage. | Found by the code review: a NUL byte gave a bare 500; Hindi and Kannada words were indexed as fragments (5 of the user's 8 transcripts are in those languages); a disk hiccup would have been cached for ever; a job from before a new stage crashed on retry. | D-061 | 2026-10-10 | Faces use OpenCV's YuNet (detector) and SFace (128-number vector) on every tier. | D-063 | 2026-10-10 | Faces are sampled at 2 frames per second on every tier (`[faces] sample_fps`), not the 0.5 / 1 / 2 of the tier table in SPEC section 6. | Measured on the user's 21 clips: 20.3 s for 473 s of footage on the M1 CPU, so the lower rates save nothing that matters, and following a face through a shot needs samples closer together than 2 s. |
| D-064 | 2026-10-10 | The face checks (`min_score` 0.8, `min_size_px` 40, `max_turn` 0.6, `min_sharpness` 20) and the tracking limits (similarity 0.363 = the SFace authors' pair threshold, overlap 0.5, gap 2 s) are stated conventions. | D-065 | 2026-10-10 | Grouping into actors is not an ingest stage. | D-066 | 2026-10-10 | A correction changes only the chosen tracks and does not regroup. | D-067 | 2026-10-10 | Grouping quality is measured on Labeled Faces in the Wild (fetched by `eval/face_clusters.py fetch` into the gitignored `data/eval/`, checksum from scikit-learn's loader), people split into a tuning and a held-out half, plus 200 one-photo people per half. | The roadmap asks for purity and ARI and the user's footage has no identity labels.
